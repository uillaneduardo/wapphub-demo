# D1 — Base de interface (27/10/2026)

## Objetivo
Estabelecer a linguagem visual e a estrutura navegável do atendimento WappHub. Protótipo totalmente estático, sem sessão real, conexão externa ou API.

## Design
- Inspiração: sobriedade de shadcn; sem dependência de shadcn ou framework.
- Navegação lateral: 60 px no desktop, 54 px em mobile.
- Lista de conversas: 338 px no desktop, 310 px em telas médias.
- Área de mensagens: ocupa todo o espaço restante; detalhes ficam ocultos por padrão.
- Mensagens: 15 px e line-height 1.6; botões de ação: 34x34 px.
- Cores: tokens CSS em :root; temas claro e escuro.
- Iconografia: símbolos SVG inline com traços consistentes, sem dependências externas.
- Acessibilidade: labels em botões, foco visível, navegação por teclado, redução de movimento.

## Estados demonstrados
- Conversa selecionada, conversas não lidas, filtro todas/não lidas/minhas, busca.
- Navegação de conversas, painel de detalhes aberto/fechado e layout móvel.
- Mensagem digitada e adicionada ao mock local (não transmitida).
- Tema persistido apenas no localStorage deste navegador.
- Ações futuras comunicadas em toast sem falsificar funcionalidades.

## Limites e backlog
D2: histórico completo, anexos, envio com estados simulados, busca em mensagens e ações de atendimento.
D3: falhas, reconexão, sincronização, RBAC demonstrativo e alertas.
D4: perfil, visão geral, contatos, organização e configurações.
D5: testes automáticos, auditoria a11y e homologação final.

## Organização
- index.html: marcação semântica.
- src/styles.css: tokens, estilos, layout e responsividade.
- src/data.js: dados fictícios, isolados dos componentes.
- src/main.js: event handlers e atualizações seletivas de DOM.

## Execução local
Pode ser aberto através de servidor HTTP estático com suporte a ES modules.
Exemplo: `python3 -m http.server 8080` e acessar http://localhost:8080.

## Docker/homelab
```sh
git clone https://github.com/uillaneduardo/wapphub-demo.git
cd wapphub-demo
docker compose up -d --build
docker compose ps
curl -I http://127.0.0.1:8280/
curl http://127.0.0.1:8280/health
```
O Compose publica **somente em 127.0.0.1:8280**. Para Cloudflare Tunnel em container isolado na mesma rede Docker, anexar o serviço demo à rede de ingress adequada, sem publicar indiscriminadamente na LAN; para cloudflared no host, usar http://127.0.0.1:8280. Não pressupor topologia do homelab. Verificar resolução do endpoint a partir do próprio cloudflared.

## Observações de segurança
Os dados são fictícios. O armazenamento local é usado apenas para preferência de tema. Esta aplicação não autentica nem envia mensagens; nenhuma UI é garantia de autorização. O backend real validará RBAC em todas as operações.
